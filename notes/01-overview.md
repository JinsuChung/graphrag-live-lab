# 01. GraphRAG 개요

## 일반 RAG의 동작 방식

```
문서 → 청크 분할 → 임베딩 → 벡터 DB
질문 → 임베딩 → 유사 청크 Top-k → LLM → 답변
```

## 일반 RAG가 약한 질문

| 유형 | 예시 | 약한 이유 |
|---|---|---|
| **멀티홉** | "A사 CEO가 이전에 다녔던 회사의 주력 제품은?" | 필요한 사실들이 서로 다른 청크에 흩어져 있고, 질문과 직접 비슷하지 않은 청크도 필요함 |
| **전역(global)** | "이 문서들 전체의 주요 테마는?" | Top-k 청크만으로는 코퍼스 전체를 볼 수 없음 |
| **관계 중심** | "X와 Y는 어떤 관계인가?" | 유사도는 관계 자체를 표현하지 못함 |

## GraphRAG의 아이디어

텍스트에서 **엔티티(노드)와 관계(엣지)**를 추출해 지식그래프를 만들고, 그 구조를 활용해 다음을 수행한다.

1. **연결 따라가기**: 멀티홉 추론
2. **구조 요약**: 커뮤니티 단위로 요약해 전역 질문에 답함
3. **정밀 질의**: Cypher/SPARQL 같은 구조 쿼리

```
문서 → 엔티티/관계 추출 → 지식그래프 → (커뮤니티 탐지 → 요약)
질문 → 엔티티 매칭 / 그래프 탐색 / 요약 검색 → 컨텍스트 조립 → LLM
```

## 장단점

| 장점 | 단점 |
|---|---|
| 멀티홉과 전역 질문에 강함 | 인덱싱 비용이 큼 (LLM 호출이 많음) |
| 근거 경로를 설명할 수 있음 | 추출 노이즈와 엔티티 중복 문제 |
| 구조화된 도메인 지식을 활용 가능 | 업데이트와 재인덱싱이 번거로움 |
| | 단순 사실 질문에서는 벡터 RAG 대비 이점이 작음 |
