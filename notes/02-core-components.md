# 02. 핵심 구성 요소

## A. 인덱싱 (그래프 구축)

### 1) 엔티티와 관계 추출
- LLM 프롬프트로 `(주어, 관계, 목적어)` 트리플과 엔티티 설명을 추출한다.
- 변형:
  - **자유 추출**: 스키마 없이 뽑음. 유연하지만 노이즈가 많다.
  - **스키마 기반 추출**: 허용할 엔티티/관계 타입을 미리 정의한다.
  - **경량 추출**: 명사구와 동시출현 같은 NLP 기법을 쓴다 (LazyGraphRAG 계열).

### 2) 엔티티 해소 (Entity Resolution)
- "삼성전자", "Samsung Electronics", "삼성"처럼 같은 개체를 병합한다.
- 방법: 문자열 정규화, 임베딩 유사도, LLM 판정.
- **그래프 품질을 좌우하는 가장 과소평가된 단계**다.

### 3) 커뮤니티 탐지
- Leiden(또는 Louvain) 알고리즘으로 밀접하게 연결된 노드 묶음을 찾는다.
- 계층적으로 수행해 레벨 0(큰 주제)부터 레벨 N(세부 주제)까지 만든다.

### 4) 커뮤니티 요약
- 각 커뮤니티에 대해 LLM이 "이 그룹은 무엇에 관한 것인가" 리포트를 생성한다.
- 전역 검색의 재료가 된다. **비용이 가장 많이 드는 단계**이기도 하다.

### 5) 부가 정보
- **Claims / Covariates**: 엔티티에 연결된 주장, 사건, 날짜.
- **Text Unit 링크**: 노드와 엣지가 어떤 원문 청크에서 왔는지 역추적용으로 기록.
- **임베딩**: 엔티티 설명, 청크, 커뮤니티 요약을 벡터화해 진입점 검색에 쓴다.

## B. 검색 (질의 시점)

| 방식 | 동작 | 적합한 질문 |
|---|---|---|
| **Local Search** | 질문과 관련된 엔티티를 찾고, 그 이웃 노드·관계·원문 청크·관련 커뮤니티 요약을 모아 컨텍스트 구성 | 특정 개체에 대한 질문 |
| **Global Search** | 커뮤니티 요약 전체에 map(부분 답변)을 돌리고 reduce(종합) | 코퍼스 전체의 테마와 요약 |
| **DRIFT Search** | Global로 대략적인 방향을 잡고 후속 질문을 생성해 Local로 확장 | 넓으면서도 구체적인 질문 |
| **Graph Traversal** | 시작 엔티티에서 BFS/빔서치, PageRank로 관련 경로 탐색 | 멀티홉 추론 |
| **Text2Cypher / SPARQL** | 자연어를 그래프 쿼리로 변환해 실행 | 집계, 필터, 정확한 구조 질의 |
| **Hybrid** | 벡터 + 키워드 + 그래프 확장 + 리랭크 | 범용 (실무 표준) |

## C. 컨텍스트 조립

- 검색한 노드, 관계, 청크, 요약을 **토큰 예산 안에서** 우선순위대로 배치한다.
- 관계는 `A --[관계]--> B` 형태의 텍스트나 표로 직렬화해 LLM에 전달한다.
- 원문 청크 인용을 함께 넣어 **근거 추적성**을 확보한다.
